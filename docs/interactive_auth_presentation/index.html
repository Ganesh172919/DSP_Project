End-to-end path

Complete Flow From Browser Capture To Final Decision

A captured face does not go directly to a yes or no decision. It passes through capture, decoding, detection, alignment, identity matching, liveness fusion, synthetic-media analysis, optional challenge verification, storage, logging, and response rendering.

Registration

Building A Stable Biometric Template

Registration captures multiple face samples, accepts only valid face crops, extracts ArcFace embeddings, averages them, normalizes the template, encrypts it, and stores it in SQLite.

  • Multiple frames reduce blink and blur noise.
  • YuNet landmarks align the face to ArcFace geometry.
  • AES-256-GCM protects the stored biometric template.

Model roles

Each AI Model Answers One Security Question

The project is easier to understand when each model is treated as a specialist rather than as one giant black box.

Layer 1 and Layer 2

YuNet Locates The Face, ArcFace Verifies Identity

YuNet gives the bounding box and five landmarks. Those landmarks are transformed into a stable 112 by 112 aligned crop. ArcFace then converts that crop into a normalized 512-dimensional embedding.

similarity = dot(auth_embedding, stored_template) grant identity when similarity >= 0.40

Layer 3

Liveness Fusion Combines CNN, Texture, Motion, And Pulse Evidence

A single image can be convincing. The liveness layer asks whether the capture behaves like a live person over time and across visual signals.

Layer 4

Deepfake Detection Looks For Synthetic And Manipulation Artifacts

The deepfake module fuses frequency-domain evidence, EfficientNet feature anomalies, boundary issues, eye reflections, skin uniformity, color correlation, and temporal flicker.

Lower deepfake probability is better. Scores above 0.30 are treated as suspicious.

Layer 5

Active Challenges Make Replay Attacks Harder

The challenge route can ask for fresh face or hand actions. MediaPipe FaceMesh and Hands verify the action from landmarks, so a static photo or old video becomes less useful.

Security and storage

Templates Are Encrypted, Attempts Are Logged, Decisions Are Explainable

Biometric templates are stored as AES-256-GCM encrypted embeddings. Successful authentication returns an RS256 JWT. Every attempt records scores, flags, decisions, and denial reasons.
